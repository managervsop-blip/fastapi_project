🚀 Запуск проекта — Runbook

Пошаговая инструкция: как запустить проект на своём ПК, как развернуть нового клиента, как следить за мониторингом.
Открывайте этот файл каждый раз, когда запускаете систему.

1. Быстрый старт (для разработки)

Для кого: вы работаете на своём ПК (Debian), тестируете код, отлаживаете. Всё в одной папке ~/Sergey_doc/fastapi_project/.
Активировать venv (в каждом новом терминале)
cd ~/Sergey_doc/fastapi_project && source venv/bin/activate
Поднять Redis + PostgreSQL + Observability
cd ~/Sergey_doc/fastapi_project && podman-compose up -d
cd ~/Sergey_doc/fastapi_project/observability && podman-compose up -d
Запустить FastAPI (терминал №1)
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
Запустить ARQ Worker (терминал №2)
arq worker.settings.WorkerSettings
Проверить (терминал №3)
curl http://127.0.0.1:8000/health → {"status":"ok"}
Готово. FastAPI на http://127.0.0.1:8000, Grafana на http://127.0.0.1:3000, Prometheus на http://127.0.0.1:9090.

2. Запуск (разработка) — подробно

# Основные контейнеры (Redis + PostgreSQL)

2.2. FastAPI (терминал №1)

# Активировать venv

3. Развёртывание (новый клиент) — пошагово

Для кого: пришёл новый клиент. Вы разворачиваете для него отдельный экземпляр приложения (FastAPI + Worker), со своей базой и своим TENANT_ID.
Создать папку для клиента
mkdir -p ~/clients/client_1 && cd ~/clients/client_1
Скопировать проект (без venv)
rsync -av --exclude='venv' --exclude='__pycache__' ~/Sergey_doc/fastapi_project/ ./
Создать базу данных клиента
podman exec fastapi_project_postgres_1 psql -U fastapi -d postgres -c "CREATE DATABASE client_1_db;"
Настроить .env (индивидуальные данные)
nano .env
Вписать: 
TENANT_ID=client_1
B24_WEBHOOK_URL=https://client1.bitrix24.ru/rest/1/abc123/
B24_APPLICATION_TOKEN=secret_token_1
DATABASE_URL=postgresql+asyncpg://fastapi:password@localhost:5432/client_1_db
REDIS_URL=redis://localhost:6379/1
PORT=8001
Создать venv и поставить зависимости
python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt
Применить миграции (создать таблицы)
alembic upgrade head
Запустить FastAPI (свой порт!)
uvicorn app.main:app --host 0.0.0.0 --port 8001
Запустить Worker (в отдельном терминале)
cd ~/clients/client_1 && source venv/bin/activate && arq worker.settings.WorkerSettings
Проверить
curl http://127.0.0.1:8001/health → {"status":"ok"}
Готово. Клиент №1 работает на порту 8001. Его метрики и трассы помечены tenant_id = client_1.

4. Мониторинг (как следить)

4.1. Открыть Grafana

http://127.0.0.1:3000
# Логин: admin / admin

4.2. Что смотреть

ЧтоГдеЧто означает
Очередь задачДашборд fastapi_project → «Очередь задач»Сколько задач в pending, done, failed.
RPSПанель «RPS»Сколько запросов в секунду.
Latency (p95)Панель «p95 Latency»95% запросов быстрее этого времени.
Ошибки 5xxПанель «Ошибки 5xx»Если пусто — ошибок нет.
ТрассыExplore → TempoПолный путь запроса: FastAPI → Worker.

4.3. Как найти трассу

  1. Откройте Grafana → Explore → Tempo.
  2. Вкладка TraceQL.
  3. Вставьте trace_id из БД: 
    podman exec fastapi_project_postgres_1 psql -U fastapi -d fastapi_db \
  -c "SELECT id, status, trace_id FROM tasks_outbox ORDER BY created_at DESC LIMIT 1;"
  4. Нажмите Run query.

Вы увидите два сервиса в одной трассе: fastapi-project и fastapi-worker.

5. Архитектура и файлы (что за что отвечает)

Как читать: сверху вниз — поток данных. Под каждым блоком — файлы, параметры и метрики.
🔔 Блок 1: Вход (Битрикс24 → FastAPI)
Что делает: Принимает вебхуки от Битрикс24, проверяет токен, пишет задачу в БД, отвечает 200 OK.

Файлы:
app/main.py — эндпоинт /webhook/bitrix (приём вебхука).
app/config.py — читает .env (B24_WEBHOOK_URL, B24_APPLICATION_TOKEN).
core/outbox.py — create_task() (запись в БД).

Параметры (в .env):
B24_WEBHOOK_URL — URL вебхука клиента.
B24_APPLICATION_TOKEN — токен приложения.
TENANT_ID — ID клиента (для мониторинга).

Метрики:
http_requests_total — сколько запросов (RPS).
http_request_duration_seconds — время ответа (p95).
http_requests_total{status=~"5.."} — ошибки 5xx.
🗄️ Блок 2: Хранилище (PostgreSQL)
Что делает: Надёжно хранит задачи (Outbox), ключи идемпотентности, статусы.

Файлы:
app/models/outbox.py — таблица tasks_outbox.
app/models/idempotency.py — таблица idempotency_keys.
migrations/versions/*.py — миграции Alembic.

Параметры (в .env):
DATABASE_URL — строка подключения.
pool_size, max_overflow (в app/db.py) — размер пула.

Метрики:
tasks_outbox_count{status="pending"} — сколько задач ждёт.
tasks_outbox_count{status="done"} — сколько выполнено.
tasks_outbox_count{status="failed"} — сколько упало.
📤 Блок 3: Издатель (publish_pending)
Что делает: Каждые 2 секунды читает pending из БД и кладёт в Redis. Возвращает «зависшие» enqueued в pending.

Файлы:
core/publisher.py — publish_pending().
worker/settings.py — cron_jobs (расписание).

Параметры (в .env):
REDIS_URL — строка подключения к Redis.

Метрики:
Логи: publisher: enqueued task ...
Логи: publisher: returned N stale enqueued tasks
📬 Блок 4: Очередь (Redis / ARQ)
Что делает: Быстрая очередь задач. AOF сохраняет задачи при перезапуске.

Файлы:
docker-compose.yml — Redis с --appendonly yes.
worker/settings.py — RedisSettings.

Параметры (в docker-compose.yml):
--appendonly yes — AOF (персистентность).

Метрики:
zcard arq:queue — размер очереди.
podman exec fastapi_project_redis_1 redis-cli info — статистика Redis.
⚙️ Блок 5: Worker (batch + rate limiter)
Что делает: Берёт до 50 задач, отправляет batch-запрос в Битрикс24 (с учётом лимитов), обновляет статусы.

Файлы:
worker/tasks.py — process_outbox_task().
core/bitrix_batch.py — execute_batch().
core/rate_limiter.py — BitrixRateLimiter.
core/outbox.py — mark_done(), mark_failed(), mark_processing().

Параметры (в worker/tasks.py):
limit(50) — размер пачки.
rate_per_sec=2.0 — лимит RPS.
capacity=5 — всплеск.

Метрики:
Логи: batch: sending N tasks
Логи: batch: processed N tasks
Логи: batch: operating=..., reset_at=..., duration=...
🔔 Блок 6: Внешний API (Битрикс24)
Что делает: Выполняет методы (crm.item.add, user.get), возвращает результат.

Файлы:
(внешний, не в проекте).

Параметры (в .env):
B24_WEBHOOK_URL — URL вебхука.

Метрики:
(внутри Битрикс24 — time.operating, time.duration).
📊 Блок 7: Observability (Collector + Prometheus + Tempo + Grafana)
Что делает: Собирает метрики и трассы, показывает в Grafana.

Файлы:
app/telemetry.py — setup_tracing().
worker/settings.py — setup_tracing(service_name="fastapi-worker").
observability/docker-compose.yml — Collector, Prometheus, Tempo, Grafana.
observability/otel-collector-config.yml — маршрутизация.
observability/prometheus.yml — сбор метрик.
observability/tempo.yml — хранение трасс.

Параметры (в app/telemetry.py):
endpoint="http://localhost:4317" — Collector.
tenant_id — фильтр по клиенту.

Метрики:
Grafana: http://127.0.0.1:3000
Prometheus: http://127.0.0.1:9090
Tempo: http://127.0.0.1:3200

5.3. Команды для выгрузки отчётов (Prometheus)

# RPS (за последние 30 минут)
START=$(date -u -d '30 minutes ago' +%s)
END=$(date -u +%s)
curl -G 'http://127.0.0.1:9090/api/v1/query_range' \
  --data-urlencode 'query=rate(http_requests_total[1m])' \
  --data-urlencode "start=$START" --data-urlencode "end=$END" \
  --data-urlencode 'step=15' > ~/Sergey_doc/backups/rps_report.json

# Latency (p95)
curl -G 'http://127.0.0.1:9090/api/v1/query_range' \
  --data-urlencode 'query=histogram_quantile(0.95, rate(http_request_duration_seconds_bucket[1m]))' \
  --data-urlencode "start=$START" --data-urlencode "end=$END" \
  --data-urlencode 'step=15' > ~/Sergey_doc/backups/latency_report.json

# Ошибки 5xx
curl -G 'http://127.0.0.1:9090/api/v1/query_range' \
  --data-urlencode 'query=rate(http_requests_total{status=~"5.."}[5m])' \
  --data-urlencode "start=$START" --data-urlencode "end=$END" \
  --data-urlencode 'step=15' > ~/Sergey_doc/backups/errors_report.json

# Очередь
curl -G 'http://127.0.0.1:9090/api/v1/query_range' \
  --data-urlencode 'query=tasks_outbox_count' \
  --data-urlencode "start=$START" --data-urlencode "end=$END" \
  --data-urlencode 'step=15' > ~/Sergey_doc/backups/queue_report.json

5.4. Как превратить JSON в читаемый отчёт

python3 -c "
import json
files = {
    'RPS': '/home/sergeykushnirov/Sergey_doc/backups/rps_report.json',
    'Latency': '/home/sergeykushnirov/Sergey_doc/backups/latency_report.json',
    'Errors': '/home/sergeykushnirov/Sergey_doc/backups/errors_report.json',
    'Queue': '/home/sergeykushnirov/Sergey_doc/backups/queue_report.json',
}
for name, path in files.items():
    try:
        data = json.load(open(path))
        if not data['data']['result']:
            print(f'{name}: НЕТ ДАННЫХ')
            continue
        print(f'=== {name} ===')
        for r in data['data']['result']:
            h = r['metric'].get('handler', r['metric'].get('status', 'all'))
            v = [float(x) for _, x in r['values'] if x != 'NaN']
            if v: print(f'  {h}: макс={max(v):.3f}, среднее={sum(v)/len(v):.3f}')
    except Exception as e:
        print(f'{name}: ОШИБКА {e}')
"
Готово. Теперь у вас есть визуальная схема всей цепочки: от вебхука Битрикс24 до мониторинга. Каждый блок связан с файлами, параметрами и метриками.

5. Чек-лист (после запуска)

  • podman ps — все контейнеры Up.
  • curl http://127.0.0.1:8000/health → {"status":"ok"}.
  • curl http://127.0.0.1:8000/health/db → {"status":"ok","db":"connected"}.
  • curl -X POST "http://127.0.0.1:8000/test/enqueue?key=check-1" → pending.
  • Подождать 3 сек, проверить БД: задача → done.
  • curl -X POST "http://127.0.0.1:8000/test/enqueue?key=check-1" → duplicate.
  • Grafana → дашборд fastapi_project — графики строятся.
  • Tempo → трасса по trace_id — два сервиса.
