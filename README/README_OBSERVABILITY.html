📊 Observability — Руководство по мониторингу

Система мониторинга для проекта FastAPI + ARQ + Redis + PostgreSQL.
Сквозная трассировка + метрики + дашборды.

1. Что это и зачем

Observability (наблюдаемость) — это способность видеть, что происходит внутри системы, не заглядывая в код. Вы открываете Grafana и видите:

  • Сколько задач в очереди (pending, done, failed).
  • Сколько запросов в секунду приходит в FastAPI (RPS).
  • Какое время ответа (p95 latency).
  • Есть ли ошибки 5xx.
  • Полный путь запроса — от вебхука Битрикс24 до выполнения в Worker (через трассы).
Для 50 клиентов: каждый клиент помечается атрибутом tenant_id. В Grafana можно фильтровать по клиенту и видеть только его данные.

Как это работает: FastAPI и Worker отправляют телеметрию в Collector (OTLP). Collector маршрутизирует метрики в Prometheus, а трассы — в Tempo. Grafana подключается к Prometheus и Tempo и показывает всё в одном дашборде.

5. Дашборды и трассы

5.1. Как найти трассу

  1. Откройте Grafana → Explore → выберите Tempo.
  2. Вкладка TraceQL.
  3. Вставьте trace_id (из БД: SELECT trace_id FROM tasks_outbox ORDER BY created_at DESC LIMIT 1;).
  4. Нажмите Run query.
Что вы увидите: два сервиса в одной трассе — fastapi-project (корень) и fastapi-worker (дочерний спан). Это и есть сквозная трассировка.

5.2. Как найти все трассы за период

# В Grafana → Explore → Tempo → TraceQL:
{}  # покажет все трассы за выбранный период

# Или по сервису:
{ resource.service.name = "fastapi-project" }

6. Отчёт по логам (скрипт)

Если нужно быстро получить сводку по задачам (без Grafana), используйте скрипт:

# scripts/report.py
import asyncio
from app.db import SessionLocal
from sqlalchemy import text

async def report():
    async with SessionLocal() as session:
        result = await session.execute(text("""
            SELECT status, COUNT(*), 
                   AVG(EXTRACT(EPOCH FROM (updated_at - created_at))) as avg_seconds
            FROM tasks_outbox 
            WHERE created_at > NOW() - INTERVAL '1 hour'
            GROUP BY status
        """))
        print("=== Отчёт за последний час ===")
        for row in result:
            print(f"{row[0]}: {row[1]} задач, среднее время: {row[2]:.2f} сек")

asyncio.run(report())

Запуск:

cd ~/Sergey_doc/fastapi_project
source venv/bin/activate
python scripts/report.py

7. Нагрузочные тесты (k6)

Зачем: Проверить, как система ведёт себя под нагрузкой (RPS, latency, очередь), и найти узкие места до того, как они проявятся у клиента.

7.1. Как запустить тест

Убедитесь, что всё запущено
FastAPI, Worker, Redis, PostgreSQL, Grafana (дашборд fastapi_project).
Запустите k6
cd ~/Sergey_doc/fastapi_project && k6 run load_test.js
Смотрите в Grafana
RPS, Latency, Очередь, Ошибки 5xx — в реальном времени.
Дождитесь завершения
k6 выведет итоговые цифры (p95, RPS, ошибки).

7.3. Где смотреть результаты теста

  • Терминал k6 — итоговые цифры (p95, RPS, ошибки).
  • Grafana (дашборд) — графики очереди, RPS, latency, ошибок.
  • Grafana (Tempo) — трассы самых медленных запросов ({ duration > 2s }).
  • БД — статусы задач (pending, done, failed).

7.4. Как снять отчёт после теста

# 1. Узнайте время окончания теста (последняя задача в БД)
podman exec fastapi_project_postgres_1 psql -U fastapi -d fastapi_db \
  -c "SELECT created_at FROM tasks_outbox ORDER BY created_at DESC LIMIT 1;"

# 2. Запросите p95 из Prometheus за этот интервал
START=$(date -u -d '2026-11-07 17:16:00' +%s)
END=$(date -u -d '2026-11-07 17:21:00' +%s)
curl -G 'http://127.0.0.1:9090/api/v1/query_range' \
  --data-urlencode 'query=histogram_quantile(0.95, rate(http_request_duration_seconds_bucket[1m]))' \
  --data-urlencode "start=$START" \
  --data-urlencode "end=$END" \
  --data-urlencode 'step=15' | python3 -m json.tool > ~/Sergey_doc/backups/latency_peak.json

# 3. Посмотрите пик p95
python3 -c "
import json
data=json.load(open('/home/sergeykushnirov/Sergey_doc/backups/latency_peak.json'))
for r in data['data']['result']:
    h=r['metric'].get('handler','all')
    v=[float(x) for _,x in r['values'] if x!='NaN']
    if v: print(f'{h}: пик p95 = {max(v):.3f} сек')
"

8. Отчёты Prometheus (как выгружать данные)

Prometheus хранит все метрики. Вы можете выгрузить их в JSON для анализа (например, в Excel или Python).

8.1. Мгновенный снимок (текущее значение)

# Метрики очереди
curl -s "http://127.0.0.1:9090/api/v1/query?query=tasks_outbox_count" | python3 -m json.tool

# RPS
curl -s "http://127.0.0.1:9090/api/v1/query?query=rate(http_requests_total[1m])" | python3 -m json.tool

8.2. Данные за период (range query)

# p95 за последние 15 минут
START=$(date -u -d '15 minutes ago' +%s)
END=$(date -u +%s)
curl -G 'http://127.0.0.1:9090/api/v1/query_range' \
  --data-urlencode 'query=histogram_quantile(0.95, rate(http_request_duration_seconds_bucket[5m]))' \
  --data-urlencode "start=$START" \
  --data-urlencode "end=$END" \
  --data-urlencode 'step=15' | python3 -m json.tool > ~/Sergey_doc/backups/latency_report.json

8.3. Как сохранить отчёт в читаемом виде

# Сохраните в текстовый файл
python3 -c "
import json
data=json.load(open('/home/sergeykushnirov/Sergey_doc/backups/latency_report.json'))
with open('/home/sergeykushnirov/Sergey_doc/backups/latency_report.txt','w') as f:
    for r in data['data']['result']:
        h=r['metric'].get('handler','all')
        v=[float(x) for _,x in r['values'] if x!='NaN']
        if v: f.write(f'{h}: пик p95 = {max(v):.3f} сек\n')
" && cat ~/Sergey_doc/backups/latency_report.txt

10. Масштабирование (50 клиентов)

Каждый клиент разворачивается как отдельный экземпляр приложения (FastAPI + Worker), но телеметрия у всех отправляется в один Collector.

10.1. Как пометить клиента

В .env каждого клиента:

TENANT_ID=client_1

В app/telemetry.py это значение добавляется в Resource:

resource = Resource.create({
    "service.name": service_name,
    "tenant.id": tenant_id,  # ← фильтр по клиенту
})

10.2. Как фильтровать в Grafana

В Grafana добавьте переменную:

  1. Dashboard settings → Variables → New variable.
  2. Name: tenant.
  3. Type: Query.
  4. Data source: Prometheus.
  5. Query: label_values(tasks_outbox_count, tenant_id) (если вы добавите tenant_id в метрики).

Или в Tempo:

{ resource.tenant.id = "client_1" }

10.3. Изоляция

СлойИзоляция
FastAPIОтдельный процесс/контейнер на клиента.
PostgreSQLОтдельная база или схема на клиента.
RedisОтдельная база (DB 0, 1, 2...) или префикс ключей.
ТелеметрияОбщий Collector, но с разным tenant.id.

11. Если что-то не работает

ПроблемаПричинаРешение
Grafana не видит PrometheusURL неправильныйПроверьте http://prometheus:9090 в Data Sources.
Grafana не видит TempoURL неправильныйПроверьте http://tempo:3200 в Data Sources.
Метрики не собираютсяPrometheus не видит /metricsПроверьте http://127.0.0.1:9090/targets — fastapi-app и fastapi-queue должны быть UP.
Трассы не видныCollector не получает спаныПроверьте podman logs observability_otel-collector_1 на ошибки.
В трассе только fastapi-projectWorker не отправляет спаныПроверьте, что setup_tracing(service_name="fastapi-worker") в worker/settings.py.
tasks_outbox_count пустойPrometheus не собирает /metrics/queueДобавьте job fastapi-queue в prometheus.yml.
Rate Limiter блокирует всёrate_per_sec слишком маленькийУвеличьте rate_per_sec в worker/tasks.py.
